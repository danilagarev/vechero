# ADR 0002: сохранять подготовку, активный раунд держать в памяти

Дата: 2026-11-08. Статус: принято как обратимое решение PB-020.

## Контекст

PB-020 требует сохранить имена/настройки с версией формата и выбрать стратегию
активного раунда. Локальный сценарий не зависит от сервера; правила и секретные
роли живут в game_core. Потеря несекретной подготовки допускает повторный ввод.

## Решение

Использовать официальный Flutter-плагин shared_preferences и SharedPreferencesAsync.
[Документация](https://pub.dev/packages/shared_preferences/versions/2.5.5) рекомендует
async API для новых пользователей и предупреждает, что запись не предназначена
для критичных данных. Поэтому сохраняется только подготовка, одним JSON-значением
под собственным ключом `vechero.spy.setup`, без ролей, локации, seed и deadline.
Список полей закрытый: schemaVersion=1, gameId=spy, names, discussionMinutes, packId.
Восстанавливать можно только корректные 4–12 имён, 3–15 минут и доступный набор.

Сохранение выполняется при явном старте партии. Во время записи повторный старт
блокируется; после ошибки можно играть с явным уведомлением, что настройки не
сохранены. При новом запуске открывается каталог; незавершённый раунд утрачен,
а прежнюю подготовку можно использовать для новой партии. Это объясняется в UI.
Неизвестная версия/повреждение дают безопасные значения по умолчанию с уведомлением,
не переписывают данные автоматически и не выводят исходник в логи.
Запись и удаление выполняются последовательно в одном adapter: очистка,
запрошенная после записи с уже закрытого экрана, исполняется последней.
Ошибка не отравляет очередь. Удаление затрагивает только собственный ключ. Имена — пользовательские локальные
данные, не отправляются в аналитику/сеть; пользователь может очистить их в подготовке.

Абстракция SpySetupStore остаётся в приложении, конкретный preferences adapter
собирается в main. UI можно проверить с изолированным хранилищем без платформы.
Ядро и контракты сети не импортируют плагин. Пример версии формата хранится в тестах.

## Альтернативы и последствия

Сохранять активный секретный раунд в preferences отвергнуто: нужны отдельная модель
приватности, защита данных, миграции и приёмка восстановления. Шифрованное хранилище
для одних имён/минут сейчас не оправдывает усложнение. БД также избыточна для одного
небольшого snapshot. Позже можно добавить защищённое восстановление отдельным ADR.
Сброс приложения или сбой записи может потерять подготовку; игра при этом доступна.
В браузере предпочтения могут быть удалены очисткой данных origin/приватным режимом.
