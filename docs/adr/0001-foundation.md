# ADR 0001: Flutter, чистое ядро и модульный сервер

Дата: 2026-11-07. Статус: принято как рабочее основание текущей итерации.

## Контекст

Нужны Android/iOS, премиальный интерфейс и два режима участия. В беседе предложены
Flutter, NestJS и PostgreSQL. Нужен полезный фундамент без преждевременной реализации
пяти игр, платежей и распределённой инфраструктуры.

## Решение

Один monorepo. Flutter-клиент; независимый Dart-пакет правил; NestJS-монолит для
будущего онлайна; JSON-схемы и авторский контент отдельно. Node/npm используются
для backend и проверки контента, Dart pub — для мобильной части.

Начинаем с «Шпиона» локально. Серверный фундамент ограничен health endpoint.
PostgreSQL и Socket.IO подключаем вместе с первым сетевым сценарием. Redis, S3,
аналитика, аккаунты и покупки не нужны для проверки одного локального раунда.

Версии инструментов и зависимостей фиксируются, lockfiles сохраняются. В CI
одинаковые проверки для человека и агента. AGENTS.md — краткая карта и реальные
ограничения проекта, без персональных ключей, моделей и глобальных разрешений.

## Альтернативы и последствия

React Native позволил бы писать оба слоя на TypeScript; Flutter выбран для
последовательного мобильного UI и соответствует предложенному в беседе направлению.
Unity здесь не даёт нужной выгоды для текстовых/карточных игр.

Два runtime означают две реализации сетевых правил. Компенсация — общая спецификация
и одинаковые тестовые векторы до запуска онлайна. Не обещаем буквальный перенос
Dart-ядра на сервер NestJS.

Начальный каркас специально не фиксирует ORM, BaaS, IAP-провайдера или SDK аналитики.
Следующий ADR нужен при появлении persistence, способа авторизации и store-покупок.
