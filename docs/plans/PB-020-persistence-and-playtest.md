# План: PB-020 — сохранение настроек и подготовка плейтеста

## Результат

После перезапуска «Вечеро» новая локальная партия предлагает прежние имена,
длительность и доступный набор. Повреждённое/неизвестное сохранение не ломает игру,
ошибка диска не блокирует локальный сценарий. Можно удалить сохранённые настройки.
Активный раунд не восстанавливается: роли и локация никогда не сохраняются.

## Границы и зависимости

Пользователь поручил начать следующий этап после исправлений ревью PB-015.
Физическая приёмка PB-015 остаётся открытой; техническая часть PB-020 идёт
параллельно, это не закрывает зависимость для окончательной приёмки.
Решение по persistence — [ADR 0002](../adr/0002-local-setup-persistence.md).
Сервер, ядро и сетевые контракты не меняются. Формат настроек локальный, версия 1,
совместимый пример — `apps/mobile/test/fixtures/spy_setup_v1.json`.

## Шаги

- [x] Версионированный snapshot настроек, строгий парсер и чтение/запись через
      SharedPreferencesAsync, включая отдельный ключ удаления.
- [x] Восстановление перед подготовкой, сохранение перед раздачей, очистка,
      защита от повторного старта и ошибок/отмены асинхронной операции.
- [x] Проверки формата/приватности, восстановления после нового экземпляра,
      неизвестной версии, повреждения, ошибки записи и удаления.
- [x] Обновить архитектуру, DEVELOPMENT, STATUS и команды проверки.
- [x] Подготовить протокол минимум трёх реальных плейтестов: время запуска,
      ошибки передачи, желание повторить, наблюдения по доступности.

## Проверка

`npm run check`, `make check-mobile`, release web build. В браузере с вымышленными
именами: начать партию → reload → новая подготовка с прежними настройками,
затем очистка → reload → пустые имена. Проверить содержимое сохранения: только
разрешённые поля. Native storage и реальные группы требуют Android/iOS и людей.

- [ ] Провести минимум три реальные сессии и закрыть физическую приёмку.

## Передача работы

Технический срез реализован: сохранение, восстановление, очистка, безопасные
ошибки и упорядочивание записи/удаления. [Отчёт проверки](../design/pb-020/verification.md).
Продуктовая приёмка требует трёх реальных компаний;
widget/browser-тесты не заменяют игровые наблюдения.
