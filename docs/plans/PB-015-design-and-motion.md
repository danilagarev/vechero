# План: PB-015 — полный дизайн интерфейса и анимаций

## Результат

Полностью проработать внешний вид и поведение «Вечеро» во всём локальном сценарии.
Текущий UI — функциональная основа PB-010; пользователь оценил его визуал как слабый.
Цель этапа — выразительный, цельный мобильный продукт с собственной графикой,
типографикой и движением. Замены палитры и стандартных Material-кнопок недостаточно.

Результат предъявляется в работающем превью, на сравнительных скриншотах и записях
анимаций. Документация сопровождает реализацию, а не заменяет её.

## Границы и зависимости

- Основа — полный цикл PB-010. Открытые проверки на Android/iOS сохраняются.
- Охват: каталог, правила, имена, настройки, передача, закрытая/открытая роль,
  обсуждение, устное голосование/ввод выбора, результат и повторная партия.
- Включены загрузка, ошибки, валидация, пустые и неактивные состояния,
  подтверждения, клавиатура, фон/возврат и отмена действий.
- Ядро правил, сетевой режим, persistence и финальный нейминг в этот этап не входят.
- Тёмное направление из PRODUCT.md — исходная гипотеза. Варианты сравниваются по
  выразительности, читаемости и удобству игры за общим столом.
- Набор инструментов и состояние подключений — [DESIGN_TOOLING](../DESIGN_TOOLING.md).
  Отсутствие внешнего аккаунта не блокирует локальные концепции и Flutter-реализацию.

### 4. Движение, тактильная и звуковая обратная связь

По уточнению пользователя 2026-11-08 выполнять этот раздел вместе с каждым
экраном из раздела 3: движение входит в готовность взаимодействия и проверяется
в том же превью, а не откладывается на завершающую полировку.

- [x] Описать motion-токены: длительности, кривые, амплитуды, прерывание и поведение
      при повторном нажатии. Для каждого эффекта указать его задачу и fallback.
- [x] Реализовать переходы экранов, отклик кнопок/выбора, открытие и закрытие роли,
      смену игрока, изменение таймера, завершение обсуждения, раскрытие результата
      и повтор партии. Декор не должен задерживать основное действие.
- [x] Секрет удалять из видимого дерева и semantics немедленно при скрытии/фоне.
      Outgoing child в AnimatedSwitcher, flip-анимация, overlay и запись перехода
      не должны удерживать чужую роль после передачи. Возврат — закрытая карточка.
- [x] Спроектировать и реализовать уместные haptics на мобильном устройстве;
      при недоступности тактильного отклика сценарий остаётся понятным.
- [x] Рассмотреть звуковую обратную связь и записать решение. Если звук добавляется,
      предусмотреть управление им и ограничения платформы; не полагаться на звук
      как единственный сигнал. Звук не является обязательной зависимостью игры.
- [x] Реализовать reduced motion: убрать вращение, масштаб и декоративные циклы,
      сохранив понятные мгновенные смены состояния. Проверить уход в фон посреди
      анимации и быстрое повторное действие.
- [x] Сначала использовать штатные Flutter animations/CustomPainter. Rive, Lottie,
      shader или дополнительные пакеты — только при конкретном полезном эффекте,
      с проверкой размера assets, лицензии, производительности и fallback.

## Проверка

- `npm run check` и `make check-mobile` для затронутого кода и документации.
- Полный integration-сценарий на доступном Android/iOS-устройстве.
- Скриншоты всех экранов и важных состояний; записи движения в обычном и reduced
  motion режимах. Профиль анимаций на устройстве, без заявлений о плавности по
  одному headless-браузеру.
- Итоговые материалы хранить вместе с исходниками дизайна в `docs/design/`,
  тяжёлые записи — по явно зафиксированным ссылкам. Использовать тестовые имена
  и воспроизводимые роли; не сохранять записи реальных приватных партий.
  Не использовать случайные
  скриншоты чужих работ как готовые assets приложения.
