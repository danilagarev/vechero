# Состояние проекта

Обновлено: 2026-11-08. PB-015: выбранный дизайн реализован во Flutter; физическая приёмка открыта.

Временное название приложения — «Вечеро»; окончательный нейминг ещё предстоит выбрать.
Обновлены заголовок Flutter и отображаемые названия Android/iOS. Технические
идентификаторы `partybox` сохранены.
Смена названия проверена вместе с актуальными Flutter-тестами PB-010.

## Реализовано

- Git `main`, npm workspaces и lockfile; Flutter/Dart packages с lockfiles.
- `AGENTS.md`, архитектура, продуктовые требования с происхождением, ADR, правила,
  проект сетевого протокола и backlog с критериями приёмки.
- Flutter-каталог «Шпион», экран правил, тёмная тема и Android/iOS host-проекты.
- Полный локальный цикл: 4–12 имён, встроенный набор, 3–15 минут, передача и роли,
  обсуждение с deadline, устное голосование, ввод общего выбора, результат и повтор.
- LocalSessionAdapter выбирает локацию из фиксированного набора; SpyController
  вызывает ядро. Inactive/paused/hidden скрывают роль, возврат оставляет её закрытой.
  Повторные нажатия не пропускают игрока. Выход из партии требует подтверждения;
  подготовку можно отменить. Позиция прокрутки сбрасывается между этапами/игроками.
- Имена и настройки повтора живут только в памяти текущего сценария.
- Чистое Dart-ядро: 4–12 игроков, случайная роль, порядок раздачи, deadline,
  переход к голосованию, выбор подозреваемого и результат.
- Личные карточки и публичная проекция; до результата она не содержит секретов.
- Авторский стартовый набор из восьми локаций и строгая JSON-схема; тесты контента.
- NestJS `/health`, TypeScript strict и HTTP-тест реального endpoint.
- Форматирование, make-команды, CI и Dependabot, шаблоны PR и плана работы.

## PB-015 — реализация «Полночного клуба»

По замечанию пользователя текущий визуал считается функциональным прототипом.
Объём PB-015 расширен до полной проработки визуала, графики, взаимодействий,
анимаций, haptics и доступности. Созданы подробный
[план](plans/PB-015-design-and-motion.md) и [инструментарий](DESIGN_TOOLING.md).
Первый шаг PB-015 выполнен: [аудит и сравнение направлений](design/pb-015/README.md),
четыре исходных Flutter-снимка и автономный интерактивный HTML с девятью эскизами.
Пользователь выбрал направление 01 — «Полночный клуб» (2026-11-08).
Он перенесён во Flutter во всём локальном цикле: авторская векторная графика,
локальный кириллический Manrope 400/700/800 с OFL, общие поверхности/кнопки/поля,
русские Material-локализации, переходы и вход карточки, reduced motion и haptics.
Секреты удаляются немедленно без outgoing-анимации. Правила и deadline не изменены.

Созданы [DESIGN_SYSTEM](DESIGN_SYSTEM.md), [галерея реальных экранов](design/pb-015/screens.html)
и [отчёт проверки](design/pb-015/verification.md). Превью настоящего приложения:
`make preview-mobile`, localhost:8716; галерея компонентов: `make gallery-mobile`.
Сохранение настроек и онлайн в эту итерацию не входят. PB-015 целиком ещё не принята:
физические Android/iOS, haptics, screen reader и profile-проверка остаются открытыми.

Установлены 10 официальных скиллов из `openai/skills`: `figma`, `figma-use`,
`figma-create-new-file`, `figma-generate-design`, `figma-generate-library`,
`figma-create-design-system-rules`, `figma-implement-design`, `playwright`,
`playwright-interactive`, `screenshot`. Для этой реализации применён Playwright CLI с Chromium и служебным ffmpeg:
браузерное превью пройдено, снимки и записи созданы. Пользовательские инструменты
не добавлены в зависимости приложения.
Figma, Product Design и MagicPath найдены в каталоге и предложены пользователю;
установка/авторизация и доступ к их MCP пока не подтверждены.

Проверки реализации: `npm run check` (форматирование, TypeScript, 3 Node-теста),
`make check-mobile` (форматирование, анализ, 7 тестов ядра и 23 мобильных теста).
15 детерминированных Flutter golden-снимков с локальными шрифтами; оба исхода,
выбранный подозреваемый, выход, загрузка/ошибка и retry. Проверены 320×640 с
масштабом 2, 12 длинных одинаковых имён, inset клавиатуры, скрытие роли и semantics
при inactive посреди анимации. Исправлено переполнение диалога при крупном тексте.
Release web build с локальным CanvasKit прошёл. Android/iOS сборки недоступны.

## Проверки при начале PB-015

Перед коммитом PB-010 повторно прошли `npm run check` (3 Node-теста) и
`make check-mobile` (7 тестов ядра, 10 мобильных тестов и анализ). Для исходных
снимков отдельно выполнен `flutter test tool/design_baseline_test.dart --update-goldens`
с локальным кириллическим шрифтом. Снимки — материал аудита, не CI-эталоны.

HTML-эскизы просмотрены в Chromium: девять карточек без горизонтального
переполнения при 320×640, открытие/скрытие роли, удаление секрета при потере
фокуса и reduced motion. Три сравнительных снимка сохранены рядом с исходниками.
Физические Android/iOS и приёмка PB-010 четырьмя людьми остаются открытыми.

По уточнению пользователя motion прорабатывается вместе с каждым экраном.
Добавлено раскрытие публичного знака результата за 420 мс и плавный отклик
выбора подозреваемого за 120 мс. В галерее можно повторить анимацию результата
и сравнить reduced motion. Отдельный тест проверяет прерывание эффекта при
включении reduced motion; мгновенное удаление секретов сохраняется.

## Исправления по ревью PB-015

Закрыты оба воспроизведённых дефекта: после «Скрыть и передать» раскрытие следующей
роли недоступно 500 мс, затем доступно обычным нажатием. Скрытие остаётся немедленным,
таймер защиты находится в UI и отменяется при dispose. Проверены физические двойные
нажатия с интервалом 100 мс на 360×800 с реальным Manrope и длинными локациями.
В iOS reduced motion сохраняется платформальный детектор edge back gesture:
в нативный переход передаются постоянные анимации, содержимое не сдвигается.
Пять регрессионных сценариев проходят. Физическая приёмка остаётся открытой.
