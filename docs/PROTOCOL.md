# Сетевой протокол: проект, ещё не реализация

Локальное ядро сейчас не зависит от протокола. До задачи PB-040 сервер обслуживает
только `/health`; описанные ниже endpoints не существуют.

## Модель и команды

Room — состав и ведущий, Session — конкретная партия, Round — раунд внутри неё.
Смена игры не требует пересоздавать комнату. Actor определяется токеном соединения,
а не полем `playerId`, присланным клиентом. Истёкший токен не восстанавливается PIN-кодом.

Предварительный envelope команды:

```json
{
  "protocolVersion": 1,
  "commandId": "uuid",
  "sessionId": "uuid",
  "expectedVersion": 7,
  "type": "spy.accuse",
  "payload": { "suspectId": "uuid" }
}
```

Сервер сначала проверяет членство и полномочия, затем ищет сохранённый результат
`commandId` в контексте сессии/actor. Повтор с тем же payload возвращает прежний ack
без второго эффекта, даже если `expectedVersion` уже устарела. Другой payload с тем
же ID отклоняется. Новая команда с устаревшей версией получает `VERSION_CONFLICT`.

Ack содержит `commandId`, `version`, `accepted` и стабильный error code. Клиент не
считает отсутствие ack отказом: повторяет команду с тем же ID. Команды разных игроков
сериализуются транзакцией/optimistic lock. Время задаёт сервер; клиент рисует deadline.

## Проекции и восстановление

Публичное событие: `protocolVersion`, `sessionId`, `version`, `serverTime`, `publicState`.
Личное событие — только авторизованному участнику: его `privateState`, без чужих ролей.
Список локаций пакета может быть публичным, выбранная локация до results — секрет.

После reconnect клиент запрашивает свежий snapshot с текущей версией, публичной
частью и только своей личной частью. Старые события игнорируются; при пропуске
версии выполняется resync. Первый сервер использует snapshots, не неограниченный
журнал replay. Истёкшая/удалённая сессия возвращает явный terminal result.

Будущие REST-операции: создание и вход в комнату, snapshot сессии, каталог/контент.
Перед реализацией зафиксировать их в OpenAPI и описать реальные payload в схемах.
PIN с ограниченным сроком, лимит попыток входа, лимит размера/частоты команд,
истечение гостевых токенов и политика ухода ведущего входят в критерии PB-040.
